# Деструктивные тесты Blobcheg

Набор, задача которого — **сломать пакет**, а не подтвердить, что он работает. Тесты писались
вслепую: сначала сценарии злоупотребления и ожидания «как обязана вести себя правильная система»,
и только потом код пакета — ради имён типов, не ради ожиданий. Там, где ожидание не сошлось с
реальностью, тест оставлен КРАСНЫМ, а над ним стоит комментарий `// BUG:` с тремя частями: что
происходит, что должно происходить, и корень — конкретный компонент и механизм.

Красный тест здесь — это находка, а не поломка набора.

## Почему это отдельный набор

В `Tests/` пакета лежит то, что обязано быть зелёным всегда. Здесь — инструмент разработчика
САМОГО пакета: он нарочно роняет пересборку, портит файлы на диске, входит в пересборку из
середины пересборки. Потребителю пакета это не нужно и мешало бы: часть тестов красная by design.

Поэтому набор живёт в `Samples~` — папка с тильдой невидима для Unity, в компиляцию потребителя не
попадает и не стоит ему ни секунды импорта. Ставится осознанно.

## Как поставить

Package Manager → **Blobcheg** → **Samples** → *Деструктивные тесты (core dev)* → **Import**.
Ляжет в `Assets/Samples/Blobcheg/<версия>/…` и появится в Test Runner (EditMode).

Из CLI, без Package Manager — `tools~/run-advanced-tests.ps1` в корне пакета: копирует набор в
указанный проект, гоняет `unity test --filter Blobcheg.AdvancedTests` и убирает за собой.

```powershell
./tools~/run-advanced-tests.ps1 -Project C:/Projects/Evuck/EvuckServer
```

## Что покрыто

Две дороги, обе сквозные — от входа до байта в бинарнике, без единого взгляда во внутренности:

- **едиторный цикл** — ассеты нод → `RebuildAll` → файлы в StreamingAssets → ref/id-ассеты →
  чтение реинтерпретацией;
- **файловый цикл** — `BlobchegWriter`/`BlobchegRouterWriter` → байты на диске → `BlobchegBlob`/
  `BlobchegRouterBlob`. Нужен там, где ассетами не изобразить: 64 базы, сто тысяч строк роутера.

| Файл | О чём |
|---|---|
| `EmptyAndLifecycleTests` | пустой домен, запись нулевой длины, пропавший файл, чтение до подъёма и после `Dispose`, все способы соврать в декларации ноды |
| `BoundaryAndTypeTests` | за концом файла, внутрь header'а, мимо выравнивания, ровно на последней записи, 0/64/65 баз роутера, чтение типом-близнецом |
| `IdentityTests` | id и оффсет чужого роутера/чужой базы, `default(BlobchegId)`, стабильность id при правке, переименовании и одинаковых именах |
| `CorruptionTests` | обрезали, дописали, перевернули байт, подменили magic/версию/флаги, соврали в прологе роутера |
| `ConcurrencyAndVolumeTests` | чтение из бёрстовой джобы, реентранс пересборки, 100k строк, запись в мегабайты |
| `HumanFactorTests` | сохранённый id, закешированный оффсет, «id не ноль значит есть», манифест как доказательство, правка бинарника руками |
| `SemanticAndAbsurdTests` | два фасада над одним файлом, круговые ссылки записей, нода на саму себя, собранный блоб на входе, указатель внутри записи |

## Что набор нашёл

Прогон на Unity 6000.3.18f1: **85 тестов, 74 зелёных, 11 красных**. Все 11 — находки; подробный
корень каждой стоит `// BUG:`-комментарием над самим тестом.

Три из них — один общий корень: **у адреса в этом формате нет личности**. Ни оффсет, ни
`BlobchegId` не несут ни признака своей базы/роутера, ни поколения раскладки, а header и пролог
хранят что угодно, кроме «чей это файл». Отсюда сразу три способа прочитать чужое молча.

| Тест | Что происходит | Корень |
|---|---|---|
| `Id_чужого_роутера_не_резолвится_в_этом` | id из `AdvOtherRouter` отдаёт строку `AdvRouter` | нет личности адреса |
| `Оффсет_из_чужой_базы_не_читается_в_этой` | адрес из `IAdvLoose` читается в боевой базе | нет личности адреса |
| `Закешированный_оффсет_после_появления_чужой_записи_не_врёт` | появление записи типа, чьё имя сортируется раньше, сдвигает соседей; закешированный адрес указывает на чужую запись | нет поколения адреса |
| `Сохранённый_id_после_удаления_соседа_не_указывает_на_другую_ноду` | удалили ноду — сохранённый id приводит к соседней; сейв молча читает не тот предмет | id это позиция в списке по GUID |
| `Дефолтный_BlobchegId_не_валиден` | `default(BlobchegId)` == строка 0, а `IsValid` == true | сентинел выбран `uint.MaxValue`, а не 0 |
| `Близнец_того_же_размера_обязан_быть_отбит` | запись читается типом того же размера молча | `CheckType` под `BLOBCHEG_DEBUG`, которого нет ни в редакторе, ни в билде |
| `Запись_с_сырым_указателем_отбивается` | структура с `byte*` уезжает в файл целиком | единственный фильтр — `where T : unmanaged`, а указатель формально unmanaged |
| `Две_пустые_сырые_записи_обязаны_иметь_разные_адреса` | две записи нулевой длины получают ОДИН адрес | `Layout` двигает позицию после выдачи оффсета |
| `Копия_освобождённой_базы_не_обязана_считать_себя_поднятой` | копия структуры базы переживает `Dispose` и считает себя живой | владеющий указатель в обычном struct'е, без версии владения |
| `Пересборка_из_середины_пересборки_отбивается` | нода позвала `RebuildAll` из `Write` — и он отработал | защита от реентранса стоит на хуке, а не на самой пересборке |
| `Переименование_ноды_не_двигает_id` | пересборка сразу после переименования НЕ ВИДИТ ноду: запись выпадает из файла, id соседей едут | `GetAllAssetPaths` отстаёт от переименования так же, как `FindAssets` — от импорта |

Отдельно стоит отметить, что **зелёного тоже много и оно важное**: целостность файла ловит всё —
обрезание, дописывание, один перевёрнутый бит, подменённые magic/версию/флаги, совравший пролог
роутера и правку значения в бинарнике руками; границы и выравнивание отбиваются; роутер работает
на 64 базах и на 100k строк; чтение из бёрстовой джобы даёт те же значения; пересборка
идемпотентна, а все четыре способа соврать в декларации ноды падают явно.

## Правила набора

- Тест судит API, а не наоборот. Пришлось подгонять ожидание под код — значит проблема в коде,
  и это фиксируется `// BUG:`, а не правкой ожидания.
- Ни один тест не имеет права уронить редактор: двойное освобождение, чтение освобождённой памяти
  и бесконечная рекурсия не выполняются, а обставляются так, чтобы их наличие было ВИДНО (см.
  `Копия_освобождённой_базы_не_обязана_считать_себя_поднятой` и `AdvReentrantNodeSo`).
- Домены и роутеры набора живут в его собственной сборке, поэтому потребителю они не видны и в его
  роутеры не вступают.
